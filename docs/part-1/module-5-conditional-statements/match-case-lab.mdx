# Modern Pattern Matching & Concise Syntax

Python 3.10 introduced **Structural Pattern Matching** (`match-case`), bringing clean, declarative dispatch routing to Python developers, replacing cumbersome multi-branch `elif` chains when inspecting discrete states or command structures.

## Structural Pattern Matching (`match-case`)

Instead of writing repetitive `elif status == ...` checks, match a target variable against structural patterns:

```python
http_status = 404

match http_status:
    case 200:
        print("Success: Resource retrieved.")
    case 401 | 403:
        print("Security Error: Unauthorized access.")
    case 404:
        print("Routing Error: Endpoint not found.")
    case 500:
        print("Server Error: Internal pipeline breakdown.")
    case _:
        print(f"Unknown Status Code: {http_status}")
```

The underscore pattern (`case _:`) acts as the universal wildcard fallback, identical to a trailing `else` statement.

## Inline Conditional Expressions (Ternary Operator)

When assigning variable values based on a simple boolean condition, inline conditional expressions compress four lines of code into a single, readable statement:

```python
# Syntax: <value_if_true> if <condition> else <value_if_false>
temperature = 38.5
health_state = "Fever Detected" if temperature > 37.5 else "Normal Temperature"

print(health_state)  # Output: Fever Detected
```

## Technical Interview Preparation

### Q1: Why is structural pattern matching preferred over extensive `elif` ladders for state machines?
**Answer:** `match-case` statements compile to highly optimized dispatch tables in Python 3.10+, eliminating repetitive variable lookups and dramatically improving code scannability when inspecting discrete constants or structured payloads.

### Q2: What happens if none of the `case` patterns match and no wildcard `case _:` is provided?
**Answer:** The runtime silently performs a no-op (no operation) and continues execution after the match block without throwing an exception or changing variable states.
