# Advanced Python: Generators & Decorators

Before completing Module 13, we must explore two essential advanced Python constructs used everywhere in modern Python frameworks, web servers, and AI pipelines: **Generators** and **Decorators**.

---

## 1. Learning Objective

By the end of this lesson, you will understand:
* What Generators are and how the **`yield`** statement enables lazy memory evaluation.
* The difference in RAM memory consumption between returning a full list vs yielding generator items one by one.
* What Decorators are and how `@wrapper` syntax modifies function behavior dynamically.
* How higher-order functions and closures work in Python memory.

---

## 2. Why This Concept Exists

1. **The Problem Generators Solve (RAM Exhaustion):**
   * Imagine processing a dataset with **10,000,000 rows** from a CSV file or database. If a function loads all 10 million rows into a Python list at once, your computer runs out of RAM and crashes (`MemoryError`).
   * **Generators** yield items **one at a time on demand** (lazy evaluation), keeping memory usage virtually at ZERO regardless of dataset size!

2. **The Problem Decorators Solve (Code Duplication in Functions):**
   * Imagine you have 50 API functions and you want to log execution time or verify user login authentication for all 50 functions.
   * Instead of adding duplicate logging code into all 50 functions, a **Decorator** wraps around any function to add features dynamically!

---

## 3. Common Beginner Confusions

### Confusion 1: "What is the difference between `return` and `yield`?"
* **`return`:** Terminates the function completely and destroys its local stack frame memory box.
* **`yield`:** Pauses the function, remembers its exact execution state and local variables, yields a single value to the caller, and waits for `next()` to resume execution.

### Confusion 2: "What does the `@my_decorator` syntax above a function actually do?"
* **Answer:** Writing `@my_decorator` above `def my_function():` is simply syntactic sugar for:
  `my_function = my_decorator(my_function)`

## 4. Mental Model: Water Tap & Gift Box Wrapper

1. **Water Tap (Generators):**
   * **List (`return`):** Filling a 1,000-liter swimming pool all at once before drinking a glass of water.
   * **Generator (`yield`):** Turning on a water tap to get one glass of water when you are thirsty, then turning the tap off. Memory stays clean!

2. **Gift Box Wrapping (Decorators):**
   * You have a plain smartphone (the target function).
   * Wrapping it in a fancy gift box with a ribbon (the decorator) adds extra features (protection, logging, authentication) without altering the smartphone inside!

## 5. Internal Python Execution Flow: Generators (`yield`)

Let's trace how Python executes a generator function:

```text
Code Executed: g = my_generator()
               item = next(g)

↓ Execution Trace:

1. Python sees 'yield' inside my_generator definition -> marks it as a Generator Function.
2. Executing g = my_generator() does NOT run function code immediately!
3. Instead, Python returns a Generator Object in Heap RAM.
4. Calling next(g) starts function execution until it hits 'yield value'.
5. Python pauses function, freezes local variables, and returns 'value'.
6. Subsequent call to next(g) unfreezes function and continues to the next yield!
```

## 7. Python Code Implementation

### Part A: Generators (`yield`)
```python
# Generator Function
def count_up_to(max_val):
    count = 1
    while count <= max_val:
        yield count  # Pauses execution and yields value
        count += 1

# --- Execution ---
counter = count_up_to(3)

print(next(counter))  # Output: 1
print(next(counter))  # Output: 2
print(next(counter))  # Output: 3

# Exhausted generator raises StopIteration if called again:
# print(next(counter)) # Raises StopIteration!
```

### Part B: Decorators (`@wrapper`)
```python
import time

# Decorator Function
def log_execution_time(func):
    def wrapper(*args, **kwargs):
        start_time = time.time()
        result = func(*args, **kwargs)  # Run original target function
        end_time = time.time()
        print(f"[LOG] Function '{func.__name__}' took {end_time - start_time:.4f}s to execute.")
        return result
    return wrapper

# Applying Decorator using @ syntax
@log_execution_time
def process_data():
    time.sleep(0.5)  # Simulate heavy AI workload
    return "Data Processed Successfully!"

# Calling decorated function
output = process_data()
print("Output:", output)
```

### Output:
```text
[LOG] Function 'process_data' took 0.5005s to execute.
Output: Data Processed Successfully!
```

---

## 8. Line-by-Line Execution Analysis

### Line: `@log_execution_time`
* **Translation:** Python rewrites the function definition to `process_data = log_execution_time(process_data)`.
* **Result:** `process_data` now points to the internal `wrapper` function, which adds logging before and after running the original logic.

---

## 9. Before / After Decorator Wrapping

### Before Applying Decorator
```python
process_data()  # Executes plain function without logging
```

### After Applying `@log_execution_time`
```python
process_data()  # Executes wrapper() -> logs start time -> runs original code -> logs end time!
```

## 11. Summary

* **Generators (`yield`)** provide lazy memory evaluation, streaming data items one at a time to prevent RAM crashes.
* **Decorators (`@decorator`)** wrap functions to inject reusable cross-cutting features (logging, timing, auth) without altering original code.
