# Practice Exercises & Placement Q&A

## 1. Top Technical Interview Q&A

### Q1: What happens in RAM when you write `s1 = Student("Sai", 21)`?
**Answer:**
1. Python allocates a fresh empty block of memory in **Heap RAM**.
2. Python passes the memory address of that Heap block into `__init__()` as the first argument (`self`).
3. Inside `__init__()`, attributes `self.name = "Sai"` and `self.age = 21` are attached to the Heap memory block.
4. Python stores the Heap memory address inside variable `s1` in **Stack RAM**.

---

### Q2: Explain the difference between `s2 = s1` and `s2 = copy.deepcopy(s1)`.
**Answer:**
* **`s2 = s1` (Reference Copy):** Copies only the memory address. Both `s1` and `s2` point to the exact same physical object in Heap RAM. Modifying `s2` alters `s1`.
* **`s2 = copy.deepcopy(s1)` (Deep Copy):** Allocates a brand-new second object in Heap RAM with identical attribute values. `s1` and `s2` point to two separate heap locations.

---

### Q3: What is the difference between Class Variables and Instance Variables?
**Answer:**
* **Class Variable:** Stored in a single central Class Memory box. Shared by all instances of the class. Modifying `Student.university_name` updates it for all students.
* **Instance Variable:** Stored inside individual object instances on Heap RAM (`self.name`). Unique to each instance.

---

### Q4: Why can't we instantiate an Abstract Base Class (ABC)?
**Answer:** An Abstract Base Class defines mandatory method signatures (`@abstractmethod`) without full implementations. It serves as an unbuilt architectural contract. Python blocks instantiation with a `TypeError` to enforce that concrete child classes implement all abstract methods before running in production.

---

### Q5: How does Python's `__init__` differ from a constructor in C++ or Java?
**Answer:** In C++ or Java, constructors allocate object memory *and* initialize attributes. In Python, memory allocation is handled by `__new__()` before `__init__()` is invoked. `__init__()` in Python is technically an *initializer*, not a *creator*.

## 2. Memory Tracing Code Exercises

### Exercise 1: Reference Mutation Trace
Predict the exact output of this program without running it:

```python
class Wallet:
    def __init__(self, balance):
        self.balance = balance

w1 = Wallet(1000)
w2 = w1
w2.balance += 500

w3 = Wallet(1500)

print("w1.balance:", w1.balance)
print("w2.balance:", w2.balance)
print("Is w1 is w2?", w1 is w2)
print("Is w1 is w3?", w1 is w3)
```

#### Answer & Memory Trace:
* `w2 = w1` copies reference `0x9000`. `w2.balance += 500` mutates `0x9000`. So `w1.balance` and `w2.balance` both print `1500`.
* `w1 is w2` outputs `True` (same memory address).
* `w3` creates a new Heap object at `0x9500`. `w1 is w3` outputs `False` (different memory addresses).

### Exercise 2: Class Variable Shadowing Bug
Find the bug in this code:

```python
class Counter:
    count = 0

    def increment(self):
        self.count += 1  # Bug here!

c1 = Counter()
c1.increment()

c2 = Counter()
c2.increment()

print("Counter.count:", Counter.count)
print("c1.count:", c1.count)
```

#### Explanation & Fix:
* `self.count += 1` creates an **instance variable** `c1.count = 1` shadowing the class variable, while `Counter.count` remains `0`!
* **Fix:** Change `self.count += 1` to `Counter.count += 1`.
